# Progress

## 2026-06-19

- Added `vrm-adapter::VrmRuntimePipeline`, a persistent renderer-agnostic
  runtime driver wrapper that owns `vrm-runtime::Runtime`, fixed-step
  accumulation, optional spring rest/state, VRM0 orientation once-only state,
  view mode, and observable per-stage reports. It drives animation frames with
  VRMA lookAt writeback, runtime expression/constraint events, three-vrm parity
  spring stepping, MToon pipeline hints, KHR emissive strength, and first-person
  visibility through the existing adapter traits. The root facade now
  re-exports `VrmRuntimePipeline`, `RuntimePipelineOptions`, and report/stage
  types for Bevy/wgpu/ash/custom-engine integration.
- Added `vrm-runtime::VrmAnimationMixer`, a renderer-independent VRMA mixer over
  existing `VrmAnimation` tracks. It supports clip/action ids, seek, repeat,
  once, ping-pong, fade/crossfade, layer-ordered blending, bone masks, additive
  mode, and root-motion apply/ignore/extract policy. `VrmRuntimePipeline` now
  owns a mixer and exposes `tick_mixer`, returning both mixer output and runtime
  stage reports while applying the sampled VRMA frame through adapter traits.
- Added `vrm-vmc`, a typed VMC layer over the existing dependency-free
  `vrm-osc` codec. The initial coverage parses and re-emits availability,
  relative time, root/bone pose, blend value/apply, camera, directional light,
  and unknown messages, traverses OSC bundles in wire order, and applies parsed
  messages through `VmcRuntimeSink` with parse-before-apply transaction hooks
  plus rollback on sink errors.
- Expanded `vrm-vmc` to cover the VMC 3.1 Marionette/Performer message
  families needed by the extension kit. Typed messages now include
  controller/key/MIDI input, HMD/controller/tracker poses including local
  device poses, receive/config/VRM/remote/settings/window/period/eye,
  calibration, information request/response, shortcut, and `/VMC/Thru/*`
  passthrough. The encoder now emits the official `/VMC/Ext/Cam` and
  `/VMC/Ext/Light` addresses while still parsing the earlier crate-local
  camera/light aliases, and `VmcParsePolicy` lets applications choose strict
  all-or-nothing packet validation or VMC-style invalid-known-message skipping
  before transaction application.
